維運鏈路與安全停損點

以下是合成事件示意，不是即時基地台拓樸

合成網路與 Incident 關聯

6 筆事件可追溯
具備證據引用仍需審核安全阻擋不可自動略過

已知的兩個阻擋原因

  • INC-1002權限不符，不允許引用RCA 指向射頻干擾，受控 SOP 存在但 NOC ACL 不允許使用。
  • INC-1004缺少權威維護文件即使找到相似 SOP，也不能替代規則所需的權威版本。
最重要的結果不是「流程全綠」，而是資訊不足時仍能維持阻擋，留下待補證的原因。

架構實驗的三個核心問題

資料能不能相信？

先驗證欄位、事件關聯和時間戳，再隔離不完整或重複紀錄，避免把雜訊當成判讀依據。

候選原因能不能解釋？

RCA 只提供有來源的排查假設，綁定告警、KPI、變更與 SOP 片段；證據不足就保留不確定性。

安全邊界是否守得住？

ACL 先於文件引用，SOP 缺口不得略過；即使測試通過，也不自動核准、部署、再訓練或修復網路。

設計取捨：為什麼沒有直接把原始 CSV 丟給模型？

03 / EXPLAINABLE TRIAGE

RCA 與知識檢索：候選不等於結論

RCA 採決定性規則式基準，使用整理後的合成資料提出排查順序；SOP 使用本機文件檢索與 ACL-first 規則。這裡沒有宣稱使用 LLM 生成答案，也沒有將規則分數解釋成真實故障機率。

單筆事件的推論路徑

01 · EVIDENCE
告警／KPI／變更有來源識別、技術別與事件關聯
02 · RCA
規則比對候選保留多個可能原因，不強制確認根因
03 · ACL FIRST
授權後檢索角色、版本、有效期、來源文件
04 · REVIEW
人工確認證據不足維持 OPEN，不自動修復

候選原因範例

  • 傳輸路徑異常 — INC-1001Cell Unavailable 與 S1 Link Down 形成關聯；仍是未確認的 RCA 候選。
  • 射頻干擾 — INC-1002SINR 下降與干擾告警提供候選，但 SOP 權限不符。
  • 組態差異 — INC-1003變更紀錄與服務異常在時間上相近，不代表因果已證實。
  • Xn 連線 — INC-1006Xn Link Down 與 HO 指標異常構成複核線索。

檢索設計的安全順序

先授權再引用
1
確認使用者可見範圍

把可使用的 SOP 文件限制在合成角色有權存取的集合。

2
核對文件版本與有效期

確認來源、版本與所需 SOP 代碼，而不是只看關鍵字相似。

3
建立有來源的候選引用

保存 SOP 代碼、修訂版與片段參照，方便追查。

4
授權不足則返回待補證

不應藉由隔離重建索引或相似文件繞過正式引用限制。

INC-1002 因 ACL 不符不能引用；INC-1004 因缺少權威文件不能替代。這兩筆缺口在 v3.4 結案時仍 OPEN。

規則分數是排序，不是機率

規則支持分數只用於固定案例內的候選排序，不可解釋為根因的校準機率。

來源參照比摘要重要

每個候選保留對應的事件或 SOP 片段，能回到原始合成資料核對。

人工判斷不省略

即使候選一致、SOP 可用，也不能跳過正式核准與風險檢查。

05 / POLICY GATE

SOP 安全閘門：阻擋也是正確結果

正式結案條件不是「所有按鈕都能通過」，而是每一筆 Incident 都要有符合 ACL、版本、來源與時效規範的文件證據。原始專案保留兩筆 OPEN 缺口，這裡不提供解除阻擋的假功能。

正式網路操作

不授權、不核准、不執行。

OPEN · INC-1002權限關卡：ACL 不符

需要 SOP-RF-004，但合成 NOC 角色無權引用。即使受控來源存在，也不能跳過角色檢查。

OPEN · INC-1004文件關卡：缺少權威來源

需要 SOP-MAINT-008，但尚無符合條件的權威文件。其他 SOP 不得被當作替代品。

目前結案狀態：BLOCKED / OPEN GAPS: 2 / Exit 2（既有驗收預期值）。

補證的合理順序

1
取得正式文件與授權來源

文件身分、版本、效期、ACL 必須由權責流程確認。

2
比對 RCA 與對應 SOP 契約

確定引用代碼與規則要求完全一致。

3
重新執行正式 RCA／E2E 與驗收

不能只因隔離檢索通過就改寫正式結果。

4
由獨立授權程序決定是否結案

沒有正式批准之前，操作仍應停止。

常見的錯誤捷徑

用相似文件替代權威 SOP

文字相似不等於授權、版本相同或符合 RCA 契約。

因測試通過便解除限制

軟體通過回歸驗收，只表示所測程式行為符合預期。

把模擬核准當正式授權

合成情境的角色與核准紀錄不能直接套用到正式 OSS。

真正遇到過的工程問題

原始專案過程的問題與修正，不是另外編造的展示案例
Windows Python 3.13：pytest INTERNALERROR 與 Path 路徑遞迴

早期測試曾改寫 Path.__str__，在 Windows 路徑轉換鏈中引發遞迴錯誤。後續測試改用 PureWindowsPath 模擬路徑，避免修改全域方法；保留跨平台來源雜湊檢查。

Windows CP950：文字讀取與 UTF-8 明確指定

診斷 Manifest 在 Windows 預設編碼下曾出現 UnicodeDecodeError。處理方式是修正測試的編碼讀取規則，並將編碼問題納入失敗類別判讀，避免把編碼錯誤誤認為資料內容損壞。

Windows／POSIX 路徑與 LF 換行造成的雜湊差異

JSON 序列化時的路徑斜線、換行格式會影響 SHA-256。後續將報告來源路徑統一為 POSIX 表示法，並對寫入器、JSON／CSV 產物進行可攜性驗證。最終驗收紀錄為 87 JSON、26 Writers PASS。

有文件，不等於文件有權引用

INC-1002 是 ACL 問題，INC-1004 是缺少符合契約的權威 SOP。這兩種問題不能混在一起處理；隔離索引、模擬覆核或測試通過，均不可直接改寫正式的 RCA／E2E 與結案狀態。
